# Grandpas Land 网站

四个静态页面，可直接部署到现有 GitHub Pages。`CNAME` 保留现有域名 `grandpasland.xyz`。

- `index.html`：官网首页与四张世界概念插画。
- `workshop.html`：玩家自带 Key 的 AI 生成、JSON 校验、编辑与下载。
- `gallery.html`：GitHub Issues 分享列表、标签/时间筛选、作品预览与下载、评论阅读。
- `docs.html`：接口、资产导入、JSON 格式与分享说明。
- `styles.css`：四页共用的玻璃样式、响应式布局与减少动态效果支持。
- `assets.js`：与游戏 Items/Entries 格式对应的公共校验逻辑。
- `content.js`：工坊与广场共用的兼容目录加载、效果说明和 GitHub 分享正文。
- `content-profile.json`：由 Unity 现有 DTO、效果注册表与资源目录导出的兼容协议，包含可用效果参数、目标枚举和日历。部署时必须与 JavaScript 文件一起更新。
- `i18n.js`：简体中文／英文界面，语言选择保存到浏览器。导航、文档、表单、无障碍标签和运行提示均可切换；玩家作品、评论、文件名与 JSON 不翻译。英文界面下的新 AI 内容使用英文，JSON 字段名不变。
- `images/`：玩家提供的四张概念插画，WebP 优化版；不标作实机截图。

## 本地预览

安装了 Node.js 时，在本目录运行 `node preview.cjs`，打开 `http://127.0.0.1:8765/`。
使用 GitHub Pages 时保持文件和 images 文件夹的相对目录，直接部署，无需构建。

## 社区与部署说明

分享和评论继续由 `sundaniu31/grandpasland` 的 GitHub Issues 承载。浏览与下载无需账号；实际发布和发表评论在 GitHub 完成。标签写入分享正文中的 gl-asset 元数据，无需仓库标签权限。

## 文件与游戏兼容

四类名字库使用 `Items`。事件、节日和阶段草稿使用 `Entries`，新生成的可执行内容携带 `SchemaVersion` / `ProfileId`。事件通过已有 `TriggerConsequences` / `Options` 调用注册效果；普通世界事件默认 `Options: []`，无须加入选择。

生成、编辑下载、分享和广场下载共用同一校验器，保留目标、嵌套效果、选项和阶段。未知字段或效果会报错，不会在校验时静默剥离。`Type` 保留为旧处理器标识，不再强制写成库类别。事件和节日必须先加载兼容目录；目录加载失败时禁用这些内容的生成、发布及下载，名字库仍可使用。

兼容目录校验结构、参数、日期和已知资源引用，不保证所有世界状态下都能执行。缺失上下文、未完整导出的资源目录和需要实际角色的效果会显示警告。AI 不能凭描述创建未安装的疾病、物品或代码。支线和特定 NPC 外部库目前只能导入保存，页面明确标为草稿。

新 AI 事件另有生成检查：组合中必须包含实际可执行的叶子效果；不能使用未实现的占位效果、未提供的资源引用或固定世界编号。需要角色上下文的后果须使用适合的城内筛选或交互选项；自动 NPC 群体仅使用支持离场数据的效果。需要绑定特定资源或世界关系的效果从生成目录排除，条件允许的全市场、聚落库存等模式仍保留。作者手动编辑或导入特定存档内容时保留原有绑定能力，并显示相应警告。

每个分享帖包含一个 JSON 库，容量超过 GitHub 正文限制时必须拆分；当前广场不读取附件和 ZIP。节日的 `LinkedEventIds` 所引用事件需在相应事件库中存在，下载者需要同时选择这两个库。游戏创建世界时每类选择一个库，存档保存快照；更新外部文件不会自动修改已有世界。联机使用游戏现有主机执行、客户端同步路径，下载者不需要生成者的 AI Key。

Unity 端协议导出后，应同步更新兼容目录与协议快照，再运行 JavaScript 校验和模拟生成/分享/下载测试，并用游戏现有加载和执行检查验证导出的文件。真实服务商调用、打包版和双客户端联机需要各自的运行验证。
