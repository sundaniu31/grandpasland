01 / Get started

一个文件，一份新的世界内容。

名字、对话和事件等内容以 .json 交付；物品还需真实 PNG 图标，完整包和 Mod 可以下载为 ZIP。游戏创建世界时选择对应库及启用的 Mod。

  1. 打开 AI 工坊，填写 AI 接口、模型名和自己的 API Key。
  2. 选择资产类型、库名，描述想要的内容，点击生成。
  3. 检查或编辑结果并校验。普通库下载 JSON；物品上传对应 PNG 后下载完整 ZIP；支持的多库可加入 Mod 草稿一起打包；世界 AI 风格单独下载 JSON。
  4. 在游戏库选择页面导入 JSON；世界 AI 风格在 AI 页导入或载入后点击应用。ZIP 先解压，按下方目录安装，再创建世界并选择内容。
当前覆盖 12 种类型：五种名字、对话、世界 AI 风格、事件、节日、物品、支线与特殊 NPC。名字提供命名候选池，对话支持气泡与 AI 资料，事件组合 103 种已注册子效果。支线和特殊 NPC 仍为描述草稿，不能据此自动领取任务或生成人物。

02 / Connect

使用自己的 AI 接口

工坊使用 OpenAI 兼容的 Chat Completions 请求格式。默认接口是 DeepSeek 的 https://api.deepseek.com/v1/chat/completions，模型为 deepseek-chat。其他服务请以其官方文档中的接口地址与模型名为准。

接口地址必须使用 HTTPS。浏览器会将 Key 作为请求凭据发送到你填写的地址，请确认它属于你信任的 AI 服务商。本站不会代理这次请求。

Key 默认仅在本次页面中使用。只有勾选“在此设备记住 Key”才会写入浏览器本地存储；可随时点击“清除已保存的 Key”。共享设备建议保持不勾选。

如果服务商不允许浏览器跨域调用，浏览器会阻止请求。请使用明确支持浏览器请求的接口，或由你信任的服务部署代理。不要把 Key 放进网址、分享文件或评论中。

生成费用、请求限额与模型可用性以服务商的当前规定为准。取消或超时仅停止浏览器等待，服务商可能已经处理请求并计费。

03 / Import

把资产放进正确的文件夹

当前项目设置的公司名是 DefaultCompany，产品名是 Crownfall1。Windows 路径如下；发行版如果更改了名称，目录也会改变。

%USERPROFILE%\AppData\LocalLow\DefaultCompany\Crownfall1\NameLibraries\

按 Win + R，粘贴上述路径并回车。目录尚未生成时，先运行游戏，或手动创建所需文件夹。

NameLibraries\
  ├─ CityNames\       城市名库
  ├─ NPCNames\        NPC 名字库
  ├─ CompanyNames\    公司名库
  ├─ FamilyNames\     家族名库
  ├─ CountryNames\    国家名库
  ├─ Dialogues\       对话库
  ├─ AIStyles\        独立世界 AI 风格
  ├─ Items\           物品 JSON 与 icons/ 图标
  ├─ Quests\          支线库
  ├─ Events\          事件库
  ├─ Festivals\       节日库
  └─ SpecialNPCs\     特定 NPC 库

例如，把 江南水乡.json 放进 NameLibraries\CityNames\。回到创建世界的库选择页面选择它；如果列表未更新，可重新打开该页面或重启游戏。

单独物品 ZIP 解压后，在游戏外部素材页选择 Items 分类，再导入包内 JSON。游戏会复制并规范化 JSON 与 PNG；若手动安装，JSON 必须直接放在 NameLibraries/Items 根目录，icons 文件夹与它同级。不要把单独物品包的整个外层目录放进 Items 后期待普通库列表递归发现它。

Mod ZIP 解压后，将整个包文件夹放进下方 Mods 根目录，再刷新、启用并创建新世界：

%USERPROFILE%\AppData\LocalLow\DefaultCompany\Crownfall1\Mods\
基础内容库在创建世界时每种类型选择一个，内容会保存为存档快照。世界 AI 风格按独立流程载入、应用，并随世界设置存档。更新外部文件不会自动改写已有世界。节日关联的事件库也必须同时选择。联机时由主机加载和执行这些数据，客户端接收结果；下载者不需要作者的 AI Key。
04 / File format

与游戏一致的 JSON 格式

名字型：Items

适用于 CityNames、NPCNames、CompanyNames、FamilyNames、CountryNames。名字只是候选池，不会创建城市或国家。单库最多 5000 个不同的有效名称；工坊自动分批请求，跨批去重并补足数量，完成后合并为一个库。取消时停止后续请求；下载前仍会校验。国家名最多 100 字符。

{
  "SchemaVersion": 1,
  "ProfileId": "crownfall1-v1",
  "Items": ["青石镇", "落霞村", "烟雨渡"]
}

内容型：Entries

事件、节日、支线和特定 NPC 共用 Entries，字段名区分大小写。以下阶段示例属于草稿；故事描述本身不执行效果。

{
  "SchemaVersion": 1,
  "ProfileId": "crownfall1-v1",
  "Entries": [
    {
      "Name": "温泉修复计划",
      "Description": "旅店老板娘希望修复镇上的老温泉。",
      "Stages": [
        {"StageName": "勘察温泉", "Description": "前往后山查看温泉源头。"}
      ],
      "Id": "hot_spring_repair",
      "Type": "",
      "Weight": 10,
      "CooldownDays": 0,
      "LinkedEventIds": []
    }
  ]
}
字段作用与默认值
Name / Description名称与描述，工坊要求非空文本。
Stages阶段数组，每项含 StageName、Description。缺省为空数组。
Id条目标识。生成时补齐，非空标识不能重复。事件关联时需保持稳定。
Type旧内容处理器标识，默认空文本。文件夹和分享类型决定库类别，不能用它覆盖原有处理器。
Weight权重，默认 10。
CooldownDays冷却天数，默认 0。
LinkedEventIds关联事件 Id 的文本数组，默认空数组。

可执行事件：组合现有子效果

完整事件通过 Target 选择地点，再组合 TriggerConsequences 中的效果。下面的事件随机选择一座城市，减少其中三名 NPC 的健康，并提高当地已有匕首物品的需求。

{
  "SchemaVersion": 1,
  "ProfileId": "crownfall1-v1",
  "Entries": [{
    "Id": "my_library_attack_01",
    "Name": "{SettlementName}遇到袭击",
    "Description": "三名居民受伤，城内匕首需求增加。",
    "Type": "",
    "EventType": "Bad",
    "TriggerPhase": "Daily",
    "TriggerConditions": [],
    "Score": -8,
    "Tags": "Health, Economy",
    "Weight": 20,
    "CooldownDays": 30,
    "Repeatable": true,
    "Target": {"RandomSettlement": true},
    "TriggerConsequences": [{
      "Type": "ModifyHealthEffect",
      "Parameters": {
        "Delta": -7,
        "TargetMode": "RandomInSettlement",
        "CharacterKind": "Npc",
        "TargetCount": 3
      }
    }, {
      "Type": "ModifyDemandEffect",
      "Parameters": {"ItemId": "weapon_dagger", "Delta": 50}
    }],
    "Options": []
  }]
}
字段用途
SchemaVersion / ProfileId可选的文件协议与游戏兼容目录标识，新生成事件会携带这两个值。
Target事件地点与角色上下文，可随机选择城市。角色目标由各子效果筛选，支持 NPC 或玩家。
TriggerConsequences立即执行的效果数组，每项使用已注册的 Type、Parameters，可用容器的 Children 组合。
Options可选的交互选项；普通世界事件使用空数组即可，不要求玩家选择。
EventType / Score / Tags事件评价与分类信息，枚举值由游戏兼容目录约束。
Repeatable是否允许再次触发；仍受冷却规则约束。

分享给其他世界时，优先使用随机城市、城内角色筛选和 {SettlementName} 占位符。固定 ActorId、PlayerId、SettlementId 通常只适用于特定存档。AI 不能仅凭名称创建新疾病、预制体或执行代码。新增物品须使用下方专用定义与 PNG 交付。目录资源不完整时会显示警告，需要在游戏中确认引用。

游戏已打包五种疾病：感冒、痢疾、风寒、食物中毒、瘟疫。目录中的 resourcesComplete.diseases:false 表示该次导出未完整采集，不能当作没有疾病，也不允许编造新病名。生成器可引用上述已知疾病，运行时仍由实际 DiseaseManager 确认。

当前已有八种物品标签：农作物、农具、原材料、奢侈品、武器、矿石、药材、食物。同包物品定义可以提供自己的新 Id 和标签；事件与消耗效果必须引用实际可用或同包已定义资源。

触发时机、条件与分支

事件的 TriggerPhase 默认为 Daily，加入每日随机候选池。WorldStart 在新世界创建、玩家出生前执行一次；PlayerStart 在每名新玩家创建后执行一次。两类启动事件只执行自动效果，不能加入交互选项，也不受 Repeatable 默认值影响。Manual 只由显式调用、排期或关联事件触发，不进入每日随机池。

TriggerConditions 是事件触发前必须全部满足的条件。它与 ConditionEffect.Parameters.Conditions 使用相同的条件格式：Type、Target、CharacterId、Param、Threshold、Op、Negate、Season、QuestState、RelationshipTarget、RelationshipCharacterId。Target 支持 Actor、Player、SpecificId、Spouse、Lover、Mother、Father；具体字段与枚举以游戏兼容目录为准。选项自己的 Conditions 仍使用原来的 Type、Param、Threshold、Op 格式。

ConditionEffect 满足条件时执行 Children，不满足时执行 ElseChildren。缺少角色或系统时，两支都会中止；Negate 也不会把缺少上下文变为成功。WeightedRandomEffect 使用 WeightedBranches，每支包含 Weight 和 Children，按非负权重只选一支，至少一支权重大于零。分支字段放在效果对象上，不要放进 Parameters。

PlayerStart 的 Actor 和 Player 由服务器绑定新玩家，不需要填写固定角色编号。WorldStart、Daily 和 Manual 不保证有角色上下文；城内筛选可以为子效果提供目标，部分效果仍要求已加载角色。故事面板可广播或发给上下文玩家，玩家定向面板应在 PlayerStart 或已有玩家上下文中使用。

后续事件通过 TriggerGameEventEffect.EventId 立即调用，或通过 ScheduleGameEventEffect 的 EventId、正数 DelayDays 排期。同一文件中的事件编号可直接互相引用；跨库编号须在游戏中启用对应库。时间效果支持指定前向日期时刻、推进分钟、暂停恢复和倍速；跨过的每一天照常结算，不能倒退。通用 RemainingDays 只用于支持恢复的效果，容器的所有分支也必须支持恢复。

生成器会检查所有分支的资源与上下文依赖。需要游戏联机预制体的交互物体只能先手动配置、绑定；网站文件不会替你安装预制体或新增疾病定义；新增物品使用 Items 分类的专用协议。

节日规则

{

  "ProfileId": "crownfall1-v1",
  "Entries": [{
    "Name": "初夏花会",
    "Description": "居民们在广场分享新采的花。",
    "Id": "summer_flower_festival",
    "Type": "",
    "Stages": [],
    "Weight": 10,

字段规则
RuleTypePeriodic：按间隔天数；BySeason：按季节；ByDayInYear：按每年第几天。
RuleDayInYearByDayInYear 使用，默认 1。兼容目录中的当前默认年长为 3 天，日期不得超过实际游戏年长。

校验会保留支持的目标、子效果、选项和阶段字段，并补齐缺省值。未知字段和未注册效果会报错，避免在下载时悄悄丢失行为。结构和参数通过校验，仍需在实际游戏中确认运行结果。

对话库：三种生成方式

Dialogues 明确使用 SchemaVersion、ProfileId，以及 Lines、Conversations、Profiles 三个数组，不使用 Items 或 Entries。工坊可分别生成单句台词、分支会话、AI 人设资料；数量指选中数组的条目数，其他数组为空。

数组使用方式
Lines场景单句：ambient、conversation、meet、enter_tavern、tavern。公共闲聊通常没有具体玩家，不使用玩家条件或 {player}。
ConversationsNPC 提问与气泡选项；通常 2–4 个回答，界面自动编号，可鼠标或数字键选择。每个会话 1–512 节点、每节点最多 16 选项；保留无条件退出。
ProfilesAI 的 Persona 和 Knowledge。提供背景资料，不配置 APIKey/模型，不直接发奖励或改变记忆。自由回复仍需在游戏启用 AI。

Match:{} 可用于通用居民；固定 NpcIds/PlayerIds 和标签需在目标世界真实存在。{name}/{npc} 指实际 NPC，{player} 指实际对话玩家，{city} 指当前聚落。中文翻译使用 zh-Hans；正文与每条翻译最多 4000 字符。

节点的 NextNodeId 必须指向同会话的真实节点，不能同时配置自动跳转和选项。选项 EventId 只有关联已注册、同时选中且可执行的事件才会生效；未知或冷却中的事件可能使选项隐藏。普通回答和退出选项使用 EventId:"" 与 Conditions:[]。对话条件只使用九种 OptionCondition，不使用完整事件条件。

物品库：JSON 与 PNG 一起交付

Items 分类使用 Entries；每个物品有稳定的独立 Id、Icon.Path 和真实 PNG。可新增 Material、Consumable、Quest、Special，不能通过外部 JSON 新增 Equipment 装备。仅 Consumable 能设置 UseEffects，使用同一子效果目录；通用 NPC/玩家消耗品优先 TargetMode:Self。

在工坊上传 PNG，生成时只使用已上传路径；未上传时生成结果属于待补图标清单。完整 ZIP 下载会检查每个 Icon.Path 的文件、真实解码、Hash、切片范围与包预算，不会用占位图片冒充。单张 PNG 最多 2 MiB、2048×2048；包最多 32 MiB，总去重解码像素最多 16777216。整张图标用 X/Y/Width/Height 均为 0。

Sources 的 Trade 和 Production 会参与实际供给；Production 要求 DailyRate、MaxStock 为正数，InitialStock 不超过 MaxStock。不指定 SettlementId 时作用于优先级至少 75 的城镇；RequiresMine 要求附近两格有矿。EventReward、Loot、Crafting 当前仅来源描述，不会自动创建奖励、掉落或配方。

  "SchemaVersion": 1,
  "ProfileId": "crownfall1-v1",
  "Entries": [
    {
      "Id": "designer.demo.field_herb",
      "Name": "田野草药",
      "Description": "常见的交易药材。",
      "Category": "Material",
      "Rarity": "Common",
      "BaseValue": 10,
      "MaximumStack": 100,
      "Weight": 1,
      "Perishable": false,
      "ShelfLifeDays": 0,
      "Tags": [
        "药材"
      ],
      "UseEffects": [],
      "Sources": [
        {
          "Type": "Trade",
          "SettlementId": "",
          "RequiresMine": false,
          "DailyRate": 0,
          "MaxStock": 30,
          "InitialStock": 10,
          "EventId": "",
          "Description": "城镇贸易"
        }
      ],
      "Icon": {
        "Path": "icons/herb.png",

上例还必须包含真实 icons/herb.png。单独下载 JSON 不构成完整物品包。ZIP 不直接作为游戏库导入；先解压，再导入物品 JSON，或安装下方 Mod 文件夹。

多库 Mod：保持分类目录

把各库加入工坊 Mod 草稿，物品连同图标一起加入，再导出 ZIP。可下载的 Mod 是数据目录，不包含 DLL、脚本、AssetBundle 或万能 manifest。事件、节日、对话与物品使用实际稳定 Id 关联。

我的内容包/
  NameLibraries/
    CountryNames/countries.json
    CityNames/cities.json
    NPCNames/people.json
    FamilyNames/families.json
    CompanyNames/companies.json
    Events/events.json
    Festivals/festivals.json
    Dialogues/dialogues.json
    Items/items.json
    Items/icons/herb.png

解压后把“我的内容包”文件夹放入 Application.persistentDataPath/Mods/，在游戏中选择启用，再创建新世界。不要直接把 ZIP 当作已启用内容。AIStyles 不属于游戏 Mod 加载器支持的分类，须单独导出并在 AI 页载入、应用。包内最多 256 个 JSON，单文件最多 10 MiB，JSON 与物品 PNG 合计最多 32 MiB。

名字合并会去重，但每种类型合并后仍最多 5000 条。后加载的同 Id 事件、节日或对话会覆盖完整条目；物品同 Id 会报错，不能覆盖内置物品。启停与修改文件不会自动重写已有存档的内容快照。

World AI style

共享世界背景与 AI 风格

工坊的“世界 AI 风格”生成一个独立 JSON 文件，也可使用离线模板后手动填写共同背景和表达要求。文件提供世界文化、语言与叙述方式，不配置模型和 API Key，不把故事设定当成已发生的事实。

{
  "SchemaVersion": 1,
  "ProfileId": "crownfall1-v1",
  "Name": "田园诸邦",
  "WorldBackground": "河谷市镇以农业和商旅往来为共同文化背景；实际地点和人物以游戏当前状态为准。",
  "StyleInstructions": "用自然、简洁的中文口语回答，遵循角色性格、已知记忆和事实，不将传闻写成结果。"
}

根对象只能包含这五个字段，全部必填且区分大小写。SchemaVersion 必须是整数 1，ProfileId 必须是 crownfall1-v1；Name 非空且最多 80 个 UTF-16 单位。WorldBackground、StyleInstructions 都是文本，各最多 8000 单位，合计最多 12000 单位，可为空。整个 UTF-8 文件含空白与 JSON 转义最多 128 KiB（131072 字节）。拒绝重复或未知字段、注释、尾随逗号、嵌套对象、无效 Unicode 与 UTF-8。Enabled、ApiKey、Model、BaseUrl 和 Profiles 不属于此文件。

  1. 网站检查并下载 JSON，可以通过分享广场的“世界 AI 风格”类型分享。
  2. 游戏打开“新游戏 → AI → 世界风格”，直接导入文件，或刷新并选择已保存风格，再载入编辑区。
  3. 检查背景、表达要求及“使用总体风格”开关，点击“应用风格”。仅导入或载入不会立即生效。

手动安装位置是 Application.persistentDataPath/NameLibraries/AIStyles/。外部素材页的 AIStyles 分类也可保存文件，但仍需回到世界风格页载入、应用。AIStyles 不能加入 Mod 包，也不会随 Mod 开关自动启用。

应用后影响后续的 NPC 自由对话、酒馆闲聊、决策和 AI 内容生成。原系统协议、实际事实、角色身份、性格、已知记忆和权限仍然优先；静态台词及已有历史不会自动重写。对话库 Profiles 继续提供按角色匹配的人设和知识。世界风格随该世界设置保存，读取存档不依赖原文件。

新游戏页面只改开局草稿；当前世界的风格在下一次世界存档时保存。文件不携带启用状态或账号凭据，下载者仍需在游戏配置可用的 AI 服务。

05 / Share

让别人发现你的作品

  1. 在 分享广场 点击“分享我的作品”。
  2. 选择分享方式：单个 JSON 库，或 GitHub 托管的 ZIP 包链接。填写名称、类型、介绍与标签。
  3. JSON 校验后打开 GitHub 发布草稿。ZIP 先上传到自己的 GitHub Release 或帖子附件，再把真实下载链接填入表单。
  4. 登录 GitHub 并提交；返回广场刷新。详情可下载 JSON 或打开 ZIP 链接。

普通 JSON 会写入帖子的 JSON 代码块，供广场预览和校验。物品完整包或多库 Mod 使用 ZIP 链接，图标无需塞入帖子正文。支持 GitHub Release 下载或 GitHub 文件附件；不接受任意第三方下载网址。

ZIP 内容不会由网页远程下载或运行；链接分享只验证地址格式，不代表包内容已经通过游戏验收。作者应先在工坊完成包校验与游戏导入测试。下载者保存 ZIP、解压安装，再在游戏启用；浏览与下载无需作者的 AI Key。

标签存储在分享正文中，无需仓库标签权限。较长的 JSON 会提供可复制的完整正文；超出 GitHub 正文容量的普通内容包可改用 ZIP 链接；世界 AI 风格应缩短文本，或直接分享下载的 JSON 文件，不能打包为 Mod ZIP。发表评论使用详情中的“去 GitHub 评论”入口。

关联库可一起打包，或分别分享并注明依赖链接。作品更新保持 Id 稳定，新作品使用新的设计者命名空间；不要在文件、介绍或评论中包含 APIKey、口令或其他凭据。

06 / A little help

常见问题

下载后游戏里看不到资产？

确认 JSON 分类目录与根结构正确：名字 Items，对话 Lines/Conversations/Profiles，世界 AI 风格是上述五字段，其余支持分类 Entries。物品需 PNG，ZIP 需先解压安装。重新打开库选择页面，再创建新世界；当前目录名称与发行版可能不同。

AI 生成失败或 JSON 校验失败？

AI 不保证总能返回正确结构。检查具体错误提示，减少条目数、简化提示词后重试。预览中的手动编辑也必须保持合法 JSON。

为什么下载内容与原始 JSON 有些区别？

下载会规范化空白并补齐缺省值，保留预览中支持的名字、描述、阶段、目标和子效果。未知字段会报错，不会静默删除。

分享广场或评论加载失败？

浏览器需要访问 GitHub API。网络限制或 GitHub 的未登录请求额度都可能导致失败，可稍后重试或打开 GitHub 原帖查看。

Steam 商店页在哪里？

目前还没有配置正式 Steam 商店链接。商店上线后，官网会提供直达入口。
